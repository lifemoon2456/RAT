# المرحلة 1 — اكتشاف اللعبة وقراءة القوالب

1. شغّل `dist/RAT.exe` أو `python -m rat`، وأنشئ مشروع RAT أو افتحه.
2. اختر مجلد اللعبة الذي يحتوي `game/`. أبق مساحة RAT منفصلة عنه.
3. للفهرسة وقراءة القوالب الموجودة اضغط «فهرسة النصوص» دون تفعيل التوليد.
4. لتوليد القوالب من مشروع تصريحي آمن، اختر مجلد SDK موثوقًا وفعّل خيار توليد
   قوالب arabic. الكتابة كلها داخل `staging` في مشروع RAT.
5. استخدم البحث للعبارة أو المعرّف أو الملف، وفلاتر النوع والثقة. اقرأ التحذيرات؛
   وجود نصوص في الجدول لا يعني اكتشاف كل نصوص اللعبة أو إمكان تصديرها.

تُحفظ النتائج ويُعاد عرضها عند فتح المشروع. الاستيراد المتكرر للمصدر نفسه يعيد
استخدام unit_id والترجمات. تغير المصدر ينتج نسخة جديدة؛ لا يكتب فوق السجل القديم
أو الترجمة المعتمدة. تحفظ ترقية SQLite v1 نسخة `project.sqlite.before-v2-*.bak`.

## الأوضاع والحدود

- يجرد `.rpy`, `.rpym`, `.rpyc`, `.rpymc`, `.rpa` ومجلدات `tl/<language>`، ويرصد
  وحدات Python دون تحميلها. الأرشيفات والملفات المجمعة تُعد فقط، ولا تفك أو تنفذ.
- الكشف عن الإصدار يعتمد على version_tuple/vc_version أو سطر Ren'Py في log. يبيّن
  التقرير الثقة ومصدر الدليل والتعارض؛ غياب الدليل يبقى «غير معروف».
- يقرأ `translate arabic <identifier>` و`translate arabic strings` مع التعليقات
  المصدرية وold/new، والاقتباسات ومحارف الهروب والأسطر الممتدة. يحتفظ بالمعرف
  الأصلي وبـold وبتمثيل string literal. النص المترجم لا يصبح أصلًا بالاستنتاج.
- عند توفر المصدر، يطابق موقعه ونصه. القالب المخالف لتعليمة معروفة يُستبعد مع
  تحذير. إن تعذر التحقق يعرض موقع القالب وثقة existing_template بدل اختلاق موقع.
- دون قوالب، يفهرس قارئ محافظ الحوارات والسرد وخيارات menu ونصوص screen الثابتة
  المدعومة؛ المعرف يظل فارغًا والثقة unverified. لا يحلل Python لاستخراج كل اقتباساته.
- قوالب لغات أخرى تظهر في الجرد ولا تُنقل معرفاتها إلى arabic تلقائيًا.
- التعابير الديناميكية وتعليمات Ren'Py المخصصة وmonologue ذي الاقتباس الثلاثي
  وبعض الصيغ المتقدمة غير مدعومة حاليًا؛ تُسجل كمشكلات ولا تعتبر التغطية مكتملة.

## قيد توليد SDK

SDK لا يعمل هنا على لعبة مجهولة تحتوي init Python. قائمة التوليد المسموح بها
محافظة: label عادي، say بسلاسل ثابتة، menu وخيارات ثابتة، pass وreturn. يلزم أن
تجتاز ملفات المصدر الفحص؛ ملفات Python والأرشيفات وRPYC اليتيم والمصدر غير المدعوم
تمنع التوليد الآلي، مع بقاء القراءة الساكنة متاحة. لا يكفي نسخ لعبة إلى staging
ليصبح تنفيذ Python المستخرج منها آمنًا. احصل على قالب رسمي متوافق من صاحب المشروع
عندما تحتاج اللعبة تعليمات تتجاوز هذا النطاق.

الـSDK المختبر فعليًا: `D:\B\777\LC\renpy-8.5.3-sdk`. لا يُضمّن SDK في EXE؛
الفهرسة وقراءة القوالب لا تحتاجانه، والتوليد يتطلب تحديده محليًا.

## CLI والاختبارات

```powershell
.\.venv\Scripts\rat.exe scan --game "C:\Games\Novel"
.\.venv\Scripts\rat.exe scan --game "C:\Games\Novel" --project "<RAT-project-folder>"
.\.venv\Scripts\rat.exe scan --game "<source-project>" --project "<RAT-project-folder>" --sdk "<SDK-folder>" --generate-templates
.\.venv\Scripts\python.exe -m pytest -c pyproject.toml --renpy-sdk="D:\B\777\LC\renpy-8.5.3-sdk"
.\.venv\Scripts\python.exe -m ruff check .
.\.venv\Scripts\python.exe -m ruff format --check .
```

من دون وسيط SDK يُتخطى اختباره الحي وحده. تستخدم بقية الاختبارات محاكاة أو قالب
SDK الفعلي المحفوظ في fixtures، ولا تحتاج إنترنت أو SDK.
