# المرحلة 6 — الملفات المجمعة

أضيفت خدمة `PackedGameService` وتبويب Packed وأوامر CLI. لا يُكتب شيء داخل اللعبة،
ولا تُشغل RPY أو RPYC أو Python مستخرج أثناء التحليل. التعليمات المبسطة في
[README](../README.md#packed-games)، والنتائج الفعلية في [تقرير التحقق](phase6-verification.md).

## الصيغ والتوافق

| المدخل | السلوك |
|---|---|
| RPA-2.0 وRPA-3.0 | قراءة الفهرس المضغوط، XOR للصيغة 3، دعم prefix وأجزاء الملف؛ عدة أرشيفات. |
| RPA قديم أو مموه أو بصيغة أخرى | رفض واضح، مع حفظ سبب الفشل. |
| RPY/RPYM مباشر أو مستخرج | نسخ إلى مساحة مستقلة ثم محللات المرحلة 1 دون تنفيذ. |
| RPYC/RPYMC له مصدر مقابل | الاحتفاظ به، ولا يُفك تلقائيًا. |
| RPYC دون مصدر، Ren’Py 8.5.3 | حاوية RPC2 وعقد AST محددة؛ تحقق فعلي بـSDK على عينات RAT المؤلفة. |
| 8.2–8.5 الأخرى | مسار محافظ للعائلة مع `decompiler_version_not_live_tested`؛ ليس ضمان توافق. |
| إصدار مجهول/متعارض أو خارج العائلة | منع محاولة الفك قبل المحول؛ لا نستنتج الإصدار من SDK أو رقم cache الداخلي. |

`DecompilerAdapter` يفصل `compatibility` و`decompile` عن بقية المشروع. المحول المرفق
`SafeRpycDecompiler` قارئ محدود مؤلف للمشروع، وليس unrpyc كاملًا. لا تُضمّن unrpyc
ولا تُنزّل أو تُنفذ أداة خارجية. يمكن إضافة محول آخر يحقق العقد لاحقًا مع مراجعة أمانه
وترخيصه؛ لا يوجد حاليًا إعداد لتشغيل أمر خارجي اعتباطي.

يُقرأ pickle بمفسر بيانات محدود، ولا يُستخدم `pickle.load(s)` أو استيراد أصناف اللعبة
أو استدعاء constructors/reducers/BUILD hooks. تتحول عقد Ren’Py المسموحة إلى سجلات
خاملة. تُرفض globals التنفيذية والبيانات المعطوبة وتتقيد حدود فك الضغط والذاكرة والعمليات.
تُستخرج الحوارات والخيارات وold/new المدعومة. تُحذف Python وDefine وScreen وغيرها
من الناتج وتُسجل `omitted_ast_node`؛ تُسطح فروع شرطية مع تحذير. نتيجة الفك للتحليل
وليست نسخة لعبة قابلة للتشغيل. لا نستنتج أصل الحوار من TL مترجم فقد تعليق المصدر.

## المساحة والتعارضات

```text
<مشروع RAT>/
  staging/packed/<بصمة مسار اللعبة>/<معرف التشغيل>/
    .rat-packed.json
    candidates/<معرف ملف>        # نسخ مستقلة لا تتصادم أسماؤها
    views/<معرف جديد>/game/...   # المسارات الأصلية المختارة
  reports/packed/<معرف التشغيل>.json
  logs/packed-recovery.jsonl
```

كل استخراج يستخدم تشغيلًا جديدًا، وكل حل للتعارض ينشئ view جديدًا. لا تُستبدل النسخ
السابقة. تُحفظ المسارات داخل `game`، مع توحيد فواصل المسار وUnicode NFC على Windows؛
يظل اسم العضو الأصلي كما ورد في Manifest. تختلف مفاتيح المساحات باختلاف مسار اللعبة.
تُرفض المسارات المطلقة و`..` وADS وأسماء أجهزة Windows والروابط/reparse points.

يسجل Manifest لكل ملف الأرشيف والمسار الأصلي والمسار المستخرج وSHA-256 ووقت UTC
والحالة وسبب الفشل والمحولات والعلاقة بين RPYC وRPY المفكوك. لا توجد بصمة استخراج
لملف وسائط جرى تجاهله. يُسجل سجل الأحداث دون محتوى الحوارات أو مفاتيح API.

اختلاف المحتوى في المسار نفسه، بما في ذلك اختلاف حالة الأحرف، يحتاج اختيارًا صريحًا.
يكتشف التعارض بين ملف ومجلد أيضًا. يتشارك المتطابقون المحتوى في ملف منشور واحد دون
حذف سجل الأرشيفات. لا تُحدّث قاعدة النصوص أثناء وجود تعارض معلق، ولا تستبدلها قراءة
جزئية لا تحتوي أي نص مدعوم. بعد الحل تُمرر النسخة الموثقة بالبصمات إلى Game Discovery
وText Extraction وحماية المرحلة 2. لا يتصل هذا المسار بخدمات ترجمة.

الافتراضي استخراج ملفات النصوص فقط. استخراج الوسائط خيار مستقل. الحدود الافتراضية:
50 ألف عضو، 64MiB للملف المختار، 512MiB للمجموع، 16MiB للفهرس المفكوك و120 ثانية
لكل مرحلة. لا تُرفض النصوص بسبب كِبر وسيط جرى تجاهله. views المتعاقبة تزيد استهلاك
القرص حتى التنظيف. آخر 20 تشغيلًا تظهر في سجل الواجهة؛ تبقى ملفات تقارير البقية محفوظة.

التنظيف يتحقق من ملكية المشروع والتشغيل والمسار المطلق ومن غياب الروابط قبل حذف
ذلك التشغيل فقط. يحتفظ بقاعدة SQLite v4 والتقارير والسجل والتصديرات. تُحفظ قوالب TL
الموثقة كلقطة داخل SQLite قبل التنظيف عندما تكون متاحة؛ يظل تصدير الترجمات المعتمدة
المطابقة ممكنًا دون الملفات المؤقتة. إذا فقدت اللقطة، يظهر تحذير وتحتاج إعادة الاستخراج.

توليد قوالب SDK ليس تلقائيًا بعد الفك. يسمح Core به للـview الموثق الكامل والمصدر
التصريحي الذي يجتاز حارس المرحلة 1؛ يُحجب عند استعادة جزئية، ويستخدم staging منفصلًا.
تبويب Packed لا يقدم زر توليد SDK جديدًا؛ يمكن استخدام API الآمن للمطور أو قوالب
رسمية موجودة. ملفات المصدر المستخرجة دون قوالب لا تصبح تلقائيًا وحدات قابلة للتصدير.

## أوامر المطور

```powershell
rat packed --project "D:\RAT_Work\project-id" extract --game "D:\Games\Novel"
rat packed --project "D:\RAT_Work\project-id" extract --game "D:\Games\Novel" --decompile
rat packed --project "D:\RAT_Work\project-id" history
rat packed --project "D:\RAT_Work\project-id" info --run RUN_ID
rat packed --project "D:\RAT_Work\project-id" resolve --run RUN_ID --selections choices.json
rat packed --project "D:\RAT_Work\project-id" clean --run RUN_ID
```

`choices.json` كائن JSON يربط معرف التعارض بمعرف الملف المختار؛ `null` تجاهل صريح.
`--include-assets` يشمل الوسائط و`--no-import` يستخرج دون فهرسة. الإصدار اليدوي يحتاج
`--engine-version 8.5.3 --confirm-version` بعد التحقق منه، ويُرفض إن خالف دليل اللعبة.

## حلول المشكلات

| السبب | الخطوة المناسبة |
|---|---|
| `unknown_engine_version` | ابحث عن إصدار موثوق في ملفات اللعبة/توثيق صاحبها؛ لا تخمن من SDK. |
| `unverified_rpyc_engine_family` | احصل على مصدر أو قوالب متوافقة؛ لا يوجد دعم شامل للإصدارات القديمة. |
| `unsafe_pickle*` أو `invalid_*` | البيانات غير مقبولة؛ لا تحاول تجاوز الحارس أو تشغيلها كـPython. |
| `packed_*_limit` | المساحة/الحجم/الوقت غير كافٍ؛ ابدأ دون الوسائط وراجع الملف الفاشل. |
| `conflicts` | اختر نسخة أو تجاهلًا صريحًا لكل تعارض ثم طبّق الحلول. |
| `partial` | راجع كل تحذير؛ قد توجد نصوص مفيدة مع فقد أجزاء أو عدم دعم بعض الملفات. |
| `no_supported_recovered_texts` | لم توجد نصوص قابلة للقراءة؛ محفوظات الفهرسة السابقة تبقى كما هي. |
| `packed_view_changed` | استخرج مجددًا؛ لا تعدل ملفات view يدويًا ثم تستوردها باعتبارها موثقة. |
| Workspace نُظف | التقارير والترجمات باقية؛ أعد الاستخراج للعودة إلى الملفات المؤقتة. |

لم يبدأ مثبت Phase 7، ولم تختبر ألعاب تجارية أو أرشيفات مشفرة أو كل إصدارات Ren’Py.
