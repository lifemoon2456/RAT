## ما جرى التحقق منه

- جرد RPY/RPYM/RPYC/RPYMC/RPA ولغات tl ووحدات Python دون تحميلها أو تنفيذها.
- إصدار المحرك من دليل معروف، ورفض الاستدلال من config.version أو اسم المجلد،
  والإعلان عن تعارض الأدلة أو غيابها.
- قارئ translate/strings يحتفظ بالأصل من التعليق وold، ويقرأ معرف المحرك حرفيًا.
  لا يستنتج الأصل من الترجمة ولا ينسخ معرفات لغة أخرى.
- الحوارات والسرد والخيارات والنصوص متعددة الأسطر، والاقتباسات ومحارف الهروب،
  وتجاوز كود Python وأسماء الصور والملفات والتعابير الديناميكية غير المدعومة.
- قالب حقيقي محفوظ في `tests/fixtures/game_with_tl`، مولّد بالـSDK من مصدر RAT
  التجريبي المؤلف محليًا؛ بيانات المنشأ وبصمة المصدر في `provenance.json`.
- **توليد فعلي مرتين** على نسختين staging من مشروع الاختبار، بما فيه مصدر CRLF.
  استُخرجت 6 وحدات حوار/سرد بمعرفات فعلية وخياران old/new من `game/script.rpy`،
  إضافة لسلاسل SDK المشتركة. أرقام الأسطر والمعرفات طابقت المصدر المقروء.
- مقارنة بايتات ملفات المشروع التجريبي قبل التوليد وبعده؛ لم يتغير ملف ولم تنشأ
  ملفات rpyc/tl/log في الأصل. كل نواتج SDK في staging.
- رفض توليد SDK للمصدر المحتوي على Python، أو Python modules، أو الأرشيفات أو
  RPYC بلا مصدر. لا يستعمل staging ذريعة لتنفيذ Python المستخرج من لعبة.
- إعادة الاستيراد دون وحدات مكررة، ورفع الثقة بعد التحقق دون نسخ المصدر أو فقد
  الترجمة المعتمدة، ورفض المدخلات المتعارضة، والحفاظ على آخر استيراد ناجح عند الفشل.
- اكتشاف تعديل المصدر أثناء الفهرسة ورفض حفظ لقطة غير متسقة.
- حفظ نسخة مصدر جديدة عند تغيره مع بقاء المصدر القديم وترجمته المعتمدة محفوظين.
- ترقية SQLite v1 إلى v2 مع نسخة احتياطية قابلة للفتح، واستمرار بصمة المصدر
  القديمة والترجمة المعتمدة وحماية SQL من التغيير.
- أزرار اختيار اللعبة وفهرستها في QThread، وبحث الجدول وتصفية النوع والثقة،
  وعرض الخطأ عند الفشل، واستعادة النتائج عند إعادة فتح المشروع.
- أمر CLI scan يستخدم خدمة الاستيراد نفسها ويعيد المعرف الموجود في القالب الحقيقي.

أظهر اختبار سطح المكتب مشكلة مضاعفة CRLF عند نسخ المصدر على Windows؛ أُصلحت
بالكتابة الثنائية للنص المتحقق، ثم اجتاز اختبار SDK الحقيقي حالة CRLF.

## EXE المحدّث

نُسخ **ملف EXE وحده** إلى مجلد مستقل، وشُغّل من مجلد عمل فارغ بعد إزالة
PYTHONHOME/PYTHONPATH/VIRTUAL_ENV وحصر PATH في Windows System32، مع SDK المالك.
نجح فتح نافذة Qt، وإنشاء المشروع وإعادة فتحه، والفهرسة وحفظها، وتوليد SDK الحقيقي،
وعرض الجدول وقراءة إشعارات التراخيص وMock. سجّل الاختبار 317 وحدة للعينّة المصغرة
وسلاسل SDK المشتركة؛ هذه ليست نتيجة تعريب أو تغطية لعبة حقيقية.

## الحدود المتبقية

- توليد SDK الآلي يدعم المشروع التصريحي المحافظ فقط. المشاريع ذات Python أو
  تعليمات مخصصة أو مصدر ناقص تُقرأ ساكنًا أو عبر قوالب موجودة؛ لا تشغّل للتوليد.
- بعض صيغ Ren'Py المتقدمة وmonologue ذي الاقتباس الثلاثي غير مدعومة، مع تحذيرات
  صريحة. لا تدّعي الفهرسة تغطية كل لعبة.
- RPYC وRPA جرد فقط. لم يُنفّذ فك أرشيف أو decompile أو حماية placeholders أو
  اتصال ترجمة أو كتابة Patch أو lint أو تشغيل تعريب داخل لعبة.
- لم يُختبر SDK غير 8.5.3، أو Python مضيف غير 3.13.12، أو نظام غير Windows الحالي.

لم تُعدَّل `AGENTS.md` أو `PROJECT_BLUEPRINT.md`، ولم تُستخدم ملفات لعبة أصلية
من خارج fixtures في اختبارات التنفيذ.
