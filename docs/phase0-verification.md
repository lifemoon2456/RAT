# تقرير تحقق المرحلة 0

الحالة: **مكتملة ضمن نطاق التأسيس** بتاريخ 2026-11-13. لم يبدأ تنفيذ المرحلة 1.

## البيئة والنتيجة الفعلية

- Windows 11 x64، build 26200، Python 3.13.12 داخل `.venv` محلية.
- PySide6/Qt 6.12.0، Pydantic 2.14.3، SQLAlchemy 2.0.57.
- تثبيت الحزمة وأدوات التطوير فعليًا عبر `pip install -e ".[dev]"`، مع إنشاء
  أمرَي `rat` و`rat-gui`. لا توجد موصلات API أو حزم NLP مثبتة عبر extras المشروع.
- إصدارات الاعتماديات المثبتة موثقة في `requirements-dev-windows-py313.lock.txt`.

| الأمر المنفذ من جذر المستودع | النتيجة |
|---|---|
| `.venv\Scripts\python.exe -m pytest --tb=short` | **47 passed in 7.70s**، دون اختبارات متخطاة |
| `.venv\Scripts\python.exe -m ruff check .` | `All checks passed!` |
| `.venv\Scripts\python.exe -m ruff format --check .` | جميع الملفات منسقة |
| `.venv\Scripts\python.exe -m pip check` | `No broken requirements found.` |

فشل تشغيل pytest الأول بسبب صلاحيات مجلد Windows المؤقت. جرى ضبط `.pytest_tmp/`
داخل المستودع، ثم نجحت المجموعة كاملة. لم تُخفَ اختبارات ولم تُستبدَل مكتبات
الواجهة بمحاكاة. تشغيل `python -m pytest` المعتاد يستخدم هذا المسار تلقائيًا.

## ما تثبته الاختبارات

- إنشاء مشروع مستقل وفتحه من **عملية CLI جديدة** بنفس بياناته وإعداداته.
- حفظ النص الأصلي و`old` ومعرّف Ren'Py وSHA-256 والترجمة وحالتها ومراجعاتها بعد
  إغلاق اتصال قاعدة البيانات وفتح جلسة جديدة.
- رفض تعديل المصدر، واستبدال أو حذف الترجمة المعتمدة، في المستودع وفي SQLite.
- بقاء عبارتين متطابقتين في سياقين مختلفين منفصلتين، ورفض تكرار الموضع نفسه.
- تفعيل المفاتيح الخارجية؛ التراجع عن DDL غير مكتمل وعن تغيير ترجمة إذا فشل
  إدراج مراجعتها. حفظ النسخة الحالية والمراجعة معاملة واحدة.
- رفض قاعدة مفقودة أو نسخة مخطط غير معروفة أو اختلاف YAML عن SQLite، دون
  إعادة تهيئة قاعدة موجودة أو إنشاء بديل فارغ.
- حفظ إعدادات مخصصة وإعادة تحميلها؛ رفض YAML غير الآمن والحقول السرية وخيارات
  تجاوز شروط السلامة. لا تتسرب قيمة سرية مصطنعة في الخطأ أو السجل.
- التزام Mock بعقد المزود، وإرجاع `unit_id` رغم عكس ترتيب الرد، ونسخ النص حرفيًا،
  وعدم إجراء طلبات HTTP. هذه محاكاة echo؛ لا تثبت صحة ترجمة أو نظام حماية.
- أزرار إنشاء/فتح/إغلاق المشروع في PySide6، وRTL، والإبقاء على المشروع المفتوح
  عند فشل فتح آخر، وتشغيل حلقة أحداث Qt الفعلية في عملية منفصلة.
- بقاء ملف لعبة مصطنع دون تغيير أو تنفيذ أثناء إنشاء مساحة عمل منفصلة.

جرى أيضًا فحص لقطة للواجهة عبر منصة Qt الأصلية `windows` دون عرض نافذة تفاعلية؛
ظهرت العربية مع خط النظام. ملف المعاينة المحلي: `.local/phase0-window.png`.

## الحدود المتبقية

- لم يُختبر التشغيل على Python 3.11 أو 3.12؛ تثبيت 3.12 المسجل تعذر تشغيله بسبب
  Access is denied. لا يعني فحص صياغة 3.11 تحقق التشغيل عليه.
- لم تُنفذ منظومة tokenizer/placeholders/validator؛ لذلك لا توجد ترجمة ملفات ألعاب
  أو تصدير يمكنه تجاوزها. لا تمثل أعلام إعدادات الجودة مدققًا منفذًا.
- الاستئناف المتحقق هنا هو إعادة فتح المشروع وبياناته، وليس طابور مهام ترجمة
  متوقفًا. المهام وcheckpoints وتنظيم الدفعات تخص المراحل التالية.
- جداول التأسيس خمسة فقط؛ تُضاف بقية الجداول بترحيلات عند تنفيذ ميزاتها كما هو
  موثق في `architecture.md`.
- لا تحقق SDK أو `lint` أو API حقيقي أو خطوط لعبة أو أرشيفات أو حزمة EXE.

المرحلة التالية المعرّفة في المخطط: اكتشاف اللعبة وقوالب الترجمة الرسمية، وتحتاج
طلبًا مستقلًا قبل تنفيذها.
