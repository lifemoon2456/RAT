# Ren'Py Arabic Translator (RAT)

دليل عربي للمبتدئين. يمكنك اتباعه دون معرفة البرمجة أو خبرة سابقة في Ren'Py.
البرنامج مشروع قيد التطوير وفق [مخطط المشروع](PROJECT_BLUEPRINT.md).

**الإصدار الحالي: 0.7.0b1 Beta — المراحل 0 إلى 7: اكتشاف النصوص وحمايتها وترجمتها ومراجعتها،
وتصدير حزمة مستقلة مع خط عربي، واستخراج RPA وتحليل RPYC المدعوم في مساحة منفصلة.**
أضيف مثبت Windows وPortable واستعادة المشروع وتثبيت التعريب على نسخة لعبة جديدة فقط.
راجع [التثبيت والتحديث والاستعادة](docs/installation.md) و[نتائج الإصدار](docs/phase7-verification.md).
اختُبرت الموصلات بالمحاكاة؛ لم يُختبر حساب API حقيقي بمفتاح.
ظهور النصوص في الجدول يعني نجاح قراءتها، ولا يعني تعريب اللعبة
أو الوصول إلى كل نصوصها. ملفات اللعبة الأصلية لا تُعدَّل أثناء هذه الخطوات.

## قبل البداية: كلمات ستقابلها

**Ren'Py** هو البرنامج الذي صُنعت به ألعاب قصصية كثيرة تعرض الحوارات والاختيارات.
RAT يقرأ بعض الملفات التي يستخدمها هذا المحرك؛ لا يدعم كل الألعاب أو كل صيغ النصوص.

| الكلمة | معناها ببساطة |
|---|---|
| مجلد اللعبة | المجلد الأساسي الذي يحتوي مجلدًا اسمه `game`؛ قد تجد بجانبه ملف تشغيل اللعبة. |
| مشروع RAT | مجلد مستقل يحفظ قائمة النصوص ونتائج الفحص، وليس اللعبة نفسها. |
| مساحة العمل | مجلد تختاره لتجميع مشاريع RAT؛ ينشئ البرنامج داخله مجلدًا خاصًا لكل مشروع. |
| الفهرسة | البحث عن الملفات وقراءة النصوص المدعومة وترتيبها في جدول. |
| ملف `.rpy` | ملف مصدر نصي يمكن أن يحتوي الحوارات وتعليمات اللعبة. |
| ملف `.rpyc` | نص مجهز للمحرك؛ يمكن محاولة قراءة بعض إصداراته دون تشغيله، وقد يفشل أو يعطي نتيجة جزئية. |
| ملف `.rpa` | حزمة تجمع ملفات اللعبة؛ يدعم تبويب الألعاب المجمعة استخراج الصيغتين RPA-2 وRPA-3. |
| مجلد `tl/arabic` | مكان قوالب اللغة العربية داخل `game` إذا كانت موجودة. |
| قالب ترجمة | ملف يحدد النص الأصلي وموضع ترجمته؛ وجود القالب لا يعني اكتمال الترجمة. |
| SDK | حزمة أدوات Ren'Py للمطورين؛ اختيارية للفهرسة، وتحتاجها عند طلب توليد قوالب جديدة. |
| معرّف Ren'Py | اسم يعطيه المحرك لوحدة حوار كي يربطها بترجمتها. قد يغيب بصورة طبيعية. |

هذه أمثلة على **ثلاثة أماكن مختلفة**. يمكنك اختيار أسماء وأقراص أخرى موجودة عندك:

```text
D:\Games\MyNovel\                 ← مجلد اللعبة الذي تختاره للفهرسة
    MyNovel.exe
    game\
        script.rpy

D:\RAT-Work\                      ← مساحة العمل التي تختارها عند إنشاء مشروع
    8f2a...\                       ← مجلد مشروع RAT؛ اسمه الطويل ينشئه البرنامج
        project.yaml
        project.sqlite

D:\Tools\renpy-8.5.3-sdk\          ← حزمة SDK الاختيارية، منفصلة عن المكانين السابقين
    renpy.py
    lib\
```

إذا أخفى Windows امتدادات الملفات، يمكنك إظهارها من خيارات العرض في مستكشف الملفات.
لا تحتاج فتح ملفات اللعبة أو تعديلها لتتبع الدليل.

## 1. تشغيل البرنامج وعمل اختصار

1. افتح مجلد البرنامج في مستكشف ملفات Windows. إذا وصلتك الحزمة بصيغة ZIP،
   اضغط عليها بزر الفأرة الأيمن واختر **استخراج الكل** أولًا.
2. افتح مجلد `dist` ثم انقر مرتين على **`RAT.exe`**. إذا استلمت الملف التنفيذي
   وحده، انقر عليه مباشرة من مكان حفظه.
3. انتظر حتى تظهر نافذة **Ren'Py Arabic Translator (RAT)**. قد يستغرق البدء
   ثواني لأن الملف الواحد يفك مكتباته في مجلد Windows المؤقت.
4. ستجد أزرار **إنشاء مشروع** و**فتح مشروع** و**إغلاق المشروع**، وتحتها منطقة
   اختيار اللعبة والجدول. تعطيل بعض الخيارات قبل فتح مشروع أمر طبيعي.

**لا تحتاج تثبيت Python أو كتابة أوامر أو إدخال مفتاح API أو الاتصال بالإنترنت
لاستخدام نسخة EXE في الفهرسة.** SDK اختياري ومنفصل عن ملف التشغيل.
النسخة الحالية Windows x64؛ تفاصيل الأجهزة التي اختُبرت فعلًا في
[التوافق](docs/compatibility.md).

لعمل اختصار على سطح المكتب:

1. ضع `RAT.exe` في مجلد ثابت تنوي الاحتفاظ به.
2. اضغط عليه بزر الفأرة الأيمن، ثم **إرسال إلى ← سطح المكتب (إنشاء اختصار)**.
   في بعض إصدارات Windows 11 افتح **إظهار المزيد من الخيارات** أولًا.
3. افتح الاختصار بالنقر مرتين. إذا نقلت ملف EXE لاحقًا، أعد إنشاء الاختصار.

يمكن نقل ملف EXE وحده إلى مجلد آخر؛ بيانات مشاريعك محفوظة خارجه. احتفظ بنسخة من
هذا الدليل بجانبه عند مشاركته مع مستخدم جديد. تراخيص المكتبات داخل قائمة
**مساعدة ← تراخيص المكتبات**.

<a id="create-project"></a>

## 2. إنشاء مشروع لحفظ عملك

1. أنشئ، من مستكشف الملفات، مجلدًا للعمل مثل `D:\RAT-Work` على قرص متاح لديك.
   اختر مكانًا يمكنك الكتابة فيه وخارج مجلد اللعبة.
2. في RAT اضغط **إنشاء مشروع**.
3. اكتب اسمًا يسهل تذكره، مثل `تجربة أولى`، ثم اضغط **OK / موافق**.
4. عندما تظهر نافذة **اختر مجلد مساحات العمل**، اختر المجلد الذي أنشأته واضغط
   زر اختيار المجلد. لا تختَر مجلد اللعبة هنا.
5. تأكد أن أعلى النافذة يعرض **المشروع:** واسمه، ثم **المجلد:** ومساره الكامل.
   أصبح بإمكانك الآن اختيار لعبة وفهرستها.

ينشئ RAT داخل مساحة العمل مجلدًا اسمه سلسلة طويلة من الأحرف والأرقام، مثل
`8f2a...`. هذا طبيعي، ولا يلزم أن يطابق الاسم الذي كتبته. **احتفظ بالمسار المعروض**
لأنه المجلد الذي ستفتحه عندما تعود إلى عملك.

## 3. تجربة أولى بالعينة المرفقة

هذه أسرع طريقة للتعرف على الواجهة قبل تجربة لعبتك. تتوفر العينة إذا كانت لديك
ملفات المشروع الكاملة؛ من استلم EXE وحده يمكنه الانتقال إلى الخطوة 4 أدناه.

1. بعد إنشاء مشروع RAT، اضغط **اختيار مجلد اللعبة**.
2. من مجلد ملفات البرنامج، انتقل إلى `tests` ثم `fixtures`.
3. اختر مجلد **`game_with_tl`** نفسه؛ لا تدخل إلى مجلد `game` الموجود داخله.
4. اترك خانة SDK فارغة، واترك مربع **توليد قوالب arabic الرسمية على نسخة عمل
   مستقلة** دون علامة صح.
5. اضغط **فهرسة النصوص** وانتظر اكتمال القراءة والحفظ.
6. مع ترك البحث فارغًا والفلاتر على **كل الأنواع** و**كل مستويات الثقة**، تعرض
   العينة **8 وحدات نصية**. بينها العبارة `Hello, [player_name]!` وخيار `Go left`.
7. ابحث عن `Go left`، ثم امسح البحث، واختر فلتر **خيارات** لترى خياري القائمة.
8. أعد الفلتر إلى **كل الأنواع**. يمكنك إغلاق المشروع وفتحه كما في الخطوة 7
   لاحقًا للتأكد من بقاء النتائج.

هذه عينة نصوص وقوالب أصلية أُعدت لاختبار RAT؛ لا تحتاج تشغيل لعبة أو SDK لقراءتها.
وجود كلمات مثل `[player_name]` و`{i}` في النص طبيعي: تستخدمها اللعبة لعرض اسم
اللاعب والتنسيق، وليست أخطاء في القراءة.

<a id="scan-game"></a>

## 4. اختيار لعبتك وفهرسة النصوص

يفضل إنشاء مشروع RAT مستقل لكل لعبة حتى يسهل الرجوع إلى نتائجها.

1. اعثر على مجلد اللعبة في مستكشف الملفات. إذا كنت تستخدم اختصارًا لها، افتح
   **خصائص** الاختصار ثم **فتح موقع الملف** عندما يكون الخيار متاحًا.
2. افتح المجلد وتأكد من وجود مجلد داخله اسمه **`game`**. وجود ملف EXE وحده
   لا يكفي لإثبات أنها لعبة Ren'Py أو أنها مدعومة.
3. في RAT، افتح مشروعًا أو أنشئه، ثم اضغط **اختيار مجلد اللعبة** واختر المجلد
   الذي **يحتوي** `game`. مثلًا اختر `D:\Games\MyNovel` بدلًا من
   `D:\Games\MyNovel\game`.
4. في أول محاولة اترك خيار **توليد قوالب arabic الرسمية على نسخة عمل مستقلة**
   دون علامة صح. لا تحتاج SDK لقراءة المصادر والقوالب الموجودة.
5. اضغط **فهرسة النصوص** مرة واحدة. ستظهر مراحل مثل **جرد الملفات…** و**قراءة
   القوالب…** و**حفظ نتائج الفهرسة…**. انتظر حتى يعود زر الفهرسة للعمل.
6. راجع الملخص والجدول، ثم اقرأ الرسائل الموجودة أسفل الجدول. قد تُكتشف ملفات
   كثيرة وتُقرأ نصوص قليلة لأن بعض الملفات ليست مدعومة بعد.

إذا كانت اللعبة تحتوي ملفات `.rpyc` أو `.rpa` فقط، فقد تنتهي الفهرسة دون نصوص.
انتقل حينها إلى [الألعاب المجمعة](#packed-games). لا تغيّر امتدادات الملفات، ولا تنقل
أو تحذف ملفات اللعبة لإجبارها على العمل. إذا بقيت الصيغة غير مدعومة، اطلب من صاحب
المشروع المصادر أو القوالب المتوافقة. قوالب اللغات الأخرى تُرصد ولا تتحول تلقائيًا إلى عربية.

## 5. فهم النتائج والبحث فيها

الملخص فوق الجدول يعرض إصدار محرك اللعبة إن أمكن معرفته، وإصدار SDK إن استُخدم،
وأعداد الملفات ولغات مجلد `tl` وعدد النصوص الحالية. **غير معروف** تعني عدم وجود
دليل كافٍ على الإصدار، ويمكن أن تظهر رغم نجاح قراءة النصوص. إصدار SDK ليس بالضرورة
إصدار محرك اللعبة.

| ما تراه | كيف تقرؤه؟ |
|---|---|
| النص الأصلي | العبارة التي قرأها RAT، بما فيها متغيرات اللعبة وعلامات التنسيق. |
| معرّف Ren'Py | معرّف من قالب المحرك عندما يكون متاحًا؛ الرمز `—` يعني أن الحقل غير متوفر. |
| المسار والسطر | موضع النص المعروف؛ قد يشير إلى ملف القالب عندما لا يمكن توثيق موضعه في المصدر. |
| الشخصية | اسم الشخصية أو رمزها في الملف؛ قد لا يكون اسمها المعروض داخل اللعبة. |
| Label | اسم جزء أو مشهد في شيفرة القصة، وليس نصًا مطلوبًا ترجمته. |
| النوع | `dialogue` حوار، `narration` سرد، `menu_choice` خيار، `string` سلسلة، `screen_text` نص شاشة. |
| الحالة | `pending` تعني بانتظار المعالجة؛ و`needs_review` تعني الحاجة إلى مراجعة، مثل ترجمة موجودة مستوردة. |
| حماية النص | `جاهز` يعني أن المصدر اجتاز فحص الحماية؛ و`يحتاج مراجعة` يعني وجود صيغة غير مدعومة أو معطوبة تمنع تجهيزه. |

الثقة تصف **مصدر النص وارتباطه بالقالب**، ولا تقيس جودة الترجمة:

| فلتر الثقة | القيمة التي قد تظهر في الجدول | المعنى |
|---|---|---|
| SDK ومصدر متطابق | `official_template` | استُخدم SDK لتوليد القالب وطُوبق النص بمصدره. |
| قالب موجود | `existing_template` | قُرئ قالب موجود؛ ليس ذلك ضمانًا بأن كل محتواه يطابق إصدار اللعبة الحالي. |
| دون معرّف رسمي | `unverified` | قراءة أولية من المصدر دون قالب موثق لهذا النص. |

خيارات القوائم وسلاسل `old/new` قد تكون بلا معرّف حوار حتى داخل قالب رسمي؛
غياب المعرّف وحده لا يعني فشل القراءة.

للبحث والتصفية:

1. اكتب جزءًا من عبارة أو اسم ملف أو شخصية أو معرّف في خانة البحث؛ تتغير النتائج مباشرة.
2. اختر نوعًا مثل **حوار** أو **خيارات** لتقليل النتائج.
3. اختر مستوى الثقة عند الحاجة. البحث والفلتران تعمل معًا؛ قد يؤدي جمعها إلى جدول فارغ.
4. لإظهار الجميع امسح البحث واختر **كل الأنواع** و**كل مستويات الثقة**.
5. انقر عنوان عمود للفرز، أو اسحب الحافة بين عنواني عمودين لتوسيع النصوص الطويلة.

انقر صفًا لمعاينة **النص المحمي** في المربع أسفل الجدول. ستظهر رموز مؤقتة مثل
`⟦PH_..._0001⟧` مكان المتغيرات والوسوم؛ هذه معاينة للحماية ولا تُرسل إلى الإنترنت.
لا تغير هذه الرموز داخل ملفات اللعبة. إذا احتاج النص مراجعة، ستظهر رموز أخطائه
أسفل المعاينة. لا يعني `جاهز` أن النص تُرجم أو صار جاهزًا للعب.
إذا لم يظهر عمود **حماية النص** ضمن عرض النافذة، مرّر شريط الجدول أفقيًا لرؤية بقية الأعمدة.
راجع [شرح المرحلة 2](docs/phase2.md) للتفاصيل والقيود.

جدول الفهرسة للعرض فقط؛ لعرض الأصل والترجمة جنبًا إلى جنب وتحريرها، افتح
تبويب **المحرر والمراجعة / QA** بعد اكتمال الفهرسة أو الترجمة.
عداد **جديد** يخص الوحدات المضافة في عملية الفهرسة، و**أعيد استخدامه** يخص الوحدات
التي سبق حفظها. **تغير مصدره** ينبه إلى رصد تغيير في المصدر مع الاحتفاظ بالسجل
السابق. قد يتداخل هذا العداد مع الجديد؛ لا تجمع العدادات للحصول على عدد النصوص.

## 6. متى تحتاج Ren'Py SDK وكيف تحدده؟

**يمكنك تخطي هذا القسم للفهرسة العادية.** SDK مجموعة أدوات Ren'Py، وهو مختلف عن
RAT وعن ملف تشغيل اللعبة. توليد قالب ينشئ أماكن للترجمات ومعرّفات المحرك؛ لا يترجم
العبارات إلى العربية.

التوليد داخل RAT يدعم حاليًا مشاريع تجريبية بسيطة ذات مصدر متاح ومقبول للفحص.
قد يُرفض مشروع Ren'Py سليم يحتوي تعليمات Python أو تعليمات أخرى غير مدعومة؛
هذه رسالة عن حدود التوليد الحالي ولا تعني أن اللعبة معطوبة. يمكن الاستمرار
بالفهرسة دون التوليد، أو قراءة القوالب العربية الموجودة.

لتجربة التوليد بالمشروع المرفق:

1. أنشئ مشروع RAT جديدًا للتجربة، ثم اختر **`tests/fixtures/sdk_project`** كمجلد
   اللعبة؛ هذا مجلد مختلف عن عينة القوالب في الخطوة 3.
2. اضغط **اختيار SDK** واختر المجلد الرئيسي لحزمة SDK، الذي يحتوي `renpy.py`
   ومجلد `lib`. لا تختَر `renpy.exe` أو ملفًا داخل `lib`.
3. على جهاز مالك هذا المشروع، المسار الذي استُخدم في الاختبار هو:

   ```text
   D:\B\777\LC\renpy-8.5.3-sdk
   ```

   هذا مثال محلي؛ على جهاز آخر اختر مكان الحزمة الموجودة لديك. لا يحتاج تغيير
   اسم المجلد، ولا يأتي SDK مدمجًا في EXE.
4. فعّل **توليد قوالب arabic الرسمية على نسخة عمل مستقلة**، ثم اضغط **فهرسة النصوص**.
5. انتظر النتيجة. تُولَّد الملفات داخل `staging` في مشروع RAT، وتبقى أصول اللعبة
   دون تعديل. قد تظهر نصوص واجهة عامة إضافية من SDK، فيزيد العدد عن نصوص القصة.
6. إذا رُفض التوليد، راجع الرسالة في [حلول المشكلات](docs/troubleshooting.md).
   لإجراء فهرسة عادية، أزل علامة التوليد واضغط **فهرسة النصوص** مجددًا.

اختُبرت هذه العملية فعليًا مع SDK **8.5.3** على العينة المرفقة. لا يعني ذلك
دعم جميع الألعاب أو إصدارات SDK. لا تحذف Python أو ملفات أخرى من لعبتك لتجاوز
الرفض؛ استخدم وضع القراءة أو اطلب قالبًا مناسبًا من صاحب المشروع.

## 7. حفظ العمل وفتحه مرة أخرى

1. انتظر انتهاء الفهرسة وعودة زر **فهرسة النصوص** للعمل؛ تُحفظ النتائج تلقائيًا
   عند نجاح العملية. لا يوجد زر حفظ يدوي مطلوب لهذه النتائج.
2. دوّن مسار **المجلد:** المعروض أعلى النافذة، ثم اضغط **إغلاق المشروع** أو أغلق البرنامج.
   عند وجود فهرسة جارية، ينتظر البرنامج اكتمالها قبل السماح بإغلاق النافذة.
3. عند العودة شغّل `RAT.exe`، ثم اضغط **فتح مشروع**.
4. اختر مجلد المشروع ذي الاسم الطويل، الذي يحتوي **`project.yaml` و`project.sqlite`**
   معًا. لا تختَر مساحة العمل الأم أو مجلد اللعبة أو ملف SQLite بمفرده.
5. ستظهر النتائج المحفوظة دون إعادة فهرسة. لإظهارها كلها امسح البحث وأعد الفلاتر
   إلى الخيارات العامة إذا لزم.

للاحتفاظ بنسخة احتياطية، أغلق المشروع ثم انسخ **مجلد مشروع RAT كاملًا** إلى مكان
آخر. قاعدة SQLite هي الملف الذي يحفظ البيانات، وYAML يحفظ معلومات المشروع؛
احتفظ بهما معًا ولا تعدلهما يدويًا. نقل اللعبة لاحقًا لا يحدث مسارها تلقائيًا:
اختر موقعها الجديد ثم أعد الفهرسة. إعادة فهرسة المصدر نفسه تعيد استخدام وحداته،
ولا تمسح الترجمات المعتمدة المخزنة.

## 8. إعداد مزود وبدء الترجمة أو المحاكاة

ابدأ بالمحاكاة لتتعرف على الخطوات دون إنترنت أو مفتاح أو تكلفة:

1. بعد فهرسة النصوص، افتح **إعداد المزودين** واختر **Mock — محاكاة دون شبكة**.
2. اضغط **Test Connection — اختبار الاتصال**. ستظهر رسالة محاكاة فقط؛ لا يعني
   ذلك نجاح الاتصال بخدمة ترجمة حقيقية.
3. افتح **الترجمة والتقدم**، واختر Mock، ثم اضغط **بدء مهمة جديدة للنصوص المفقودة**.
4. راقب Total وRemaining وErrors. يحسب البرنامج نتائج Mock في **محاكاة فقط**،
   ويترك Translated صفرًا لأنها تعيد الكلمات الأصلية ولا تترجمها إلى العربية.

للترجمة الفعلية، اختر Gemini أو OpenAI أو DeepSeek أو OpenRouter أو Custom من
تبويب المزودين، وأدخل مفتاحك في الحقل المخفي ثم احفظه. اضغط **جلب الموديلات**
أو اكتب اسم موديل متاح لحسابك يدويًا، ثم اختبر الاتصال. اختبار الاتصال والترجمة
الحقيقيان يحتاجان إنترنت، وقد يستهلكان رصيد الخدمة. لا ترسل المفتاح في المحادثة؛
يحفظه RAT عبر keyring في مخزن النظام، ويبلغك إذا تعذر التخزين الآمن.

Custom يدعم Base URL وموديلًا ومفتاحًا مستقلًا. Google Translate متاح عبر موصل
غير رسمي لا يحتاج مفتاح API؛ قد ينقطع، ولا يقدم سياق LLM نفسه.
لا توجد أسماء موديلات ثابتة أو خدمة مجانية مضمونة.

بعد حفظ المزود، اختره من **الترجمة والتقدم** واضبط الدفعات والتزامن حسب حدود
حسابك، ثم ابدأ. تُرسل النصوص المحمية والسياق المحدود والقاموس إلى المزود المختار.
يمكن اختيار قاموس أسماء CSV؛ وشرح صيغته في [دليل المرحلة 3](docs/phase3.md).

**Pause** يحفظ الجاري ويتوقف مؤقتًا، و**Stop** يوقف توزيع الطلبات الجديدة مع حفظ
الجاري. للعودة اختر المهمة المحفوظة ثم **Resume**؛ ويمكن تفعيل إعادة محاولة الفاشل.
عند الإغلاق أثناء العمل يطلب البرنامج توقفًا مؤقتًا؛ انتظر حفظ الطلبات الجارية
ثم أغلق مجددًا. قد يعاد إرسال دفعة لم تُحفظ إذا انقطع البرنامج أثناء اتصال بالخدمة.

لا يستبدل البرنامج الترجمات الموجودة والمعتمدة. نتائج Mock غير المعتمدة يمكن
استبدالها بمهمة مزود حقيقي؛ لا تستعمل ذاكرته كأنها ترجمة حقيقية.
تُحفظ النتائج في SQLite؛ انتقل إلى المحرر للمراجعة، ثم التصدير لإنتاج الحزمة.
**لا تنسخ مجلد staging إلى اللعبة.**

## 9. تحرير الترجمات ومراجعتها

1. افتح **المحرر والمراجعة / QA**. يعرض الأصل والترجمة والشخصية والملف والحالة
   والمزود ومشكلات الجودة. انتظر تحميل القائمة؛ **تحديث / QA** يعيد فحصها.
2. انقر سطرًا؛ يظهر الأصل والترجمة وتحتهما **Previous / Next context**، أي
   العبارات السابقة واللاحقة التي تساعدك على فهم المقصود.
3. اكتب الترجمة في مربع التحرير. تُحفظ تلقائيًا بعد نصف ثانية من التوقف، وعند
   الانتقال أو إغلاق المشروع. يمكن أيضًا النقر مرتين على خلية الترجمة وتحريرها.
4. حافظ على `[player_name]` و`{i}` و`{/i}` وغيرها كما في الأصل وبالترتيب نفسه.
   يمكن حفظ مسودة معطوبة لتصحيحها لاحقًا، لكن لا يمكن اعتمادها أو تصديرها.
5. راجع عمود QA. الأخطاء مثل `missing_placeholders` تمنع الاعتماد؛ التحذيرات مثل
   `suspicious_untranslated` أو الطول تحتاج قرارك. **low / medium / high** تقدير
   لاحتمال تجاوز نافذة اللعبة، وليس قياسًا للخط أو إثباتًا أن النص سيظهر كاملًا.
6. بعد المراجعة اضغط **Approve — اعتماد**. لتعديل معتمد اضغط **Reject** أولًا.
   **Lock** يحمي السطر من التعديل؛ **Unlock** يفتح قفله. **Skip** يستبعده من
   الترجمة والتصدير؛ لإعادته افتح قفله إن لزم، ثم Reject أو احفظ مسودة جديدة.
7. لتطبيق إجراء على عدة أسطر، استخدم Ctrl مع النقر، أو Shift لتحديد نطاق، أو
   Ctrl+A داخل الجدول، ثم اضغط الإجراء. عند وجود سطر مقفل أو معطوب تُرفض عملية
   الاعتماد الجماعي كاملة؛ أصلح التحديد أو المشكلة ثم أعد المحاولة.
8. استخدم البحث والفلاتر للشخصية والملف والحالة والمزود. تعمل الشروط معًا؛
   امسحها عند اختفاء السطور. Previous وNext ينقلانك بين النتائج المعروضة.

| الحالة | معناها |
|---|---|
| Untranslated | لا ترجمة محفوظة بعد. |
| Translated | مسودة بلا مشكلات QA مسجلة؛ ليست اعتمادًا تلقائيًا. |
| Needs Review | مسودة تحتاج مراجعة، أو رُفض اعتمادها. |
| Approved | اعتمدتها يدويًا بعد اجتياز الأخطاء الحاجزة. |
| Error | فشلت محاولة الترجمة دون وجود ترجمة محفوظة. |
| Locked | مقفلة؛ تحتفظ بحالتها السابقة داخليًا، وقد تكون معتمدة أيضًا. |

لطلب بدائل: حدد سطرًا أو مجموعة، اختر ملف المزود وعدد البدائل من 1 إلى 5، ثم
**Retranslate**. هذا طلب جديد إلى الخدمة وقد يستهلك رصيدًا. تُحفظ البدائل منفصلة
ولا تستبدل النص الحالي، حتى لو كان معتمدًا. اختر سطرًا لعرض بدائله، ثم اضغط
**تطبيق البديل كمسودة**؛ المعتمد يحتاج Reject والمقفل يحتاج Unlock أولًا.
Mock ينتج محاكاة واضحة، وقد تتطابق البدائل؛ لا يوجد ضمان لاختلاف صياغة المزود.

## 10. تصدير الحزمة والنسخ الاحتياطي

1. بعد المراجعة افتح **التصدير والنسخ الاحتياطي**.
2. اترك **Export Approved Only — المعتمد فقط** مفعّلًا للمرة الأولى. إزالته تسمح
   بمسودات سليمة؛ لا تسمح بنص يفشل فحص الحماية أو بمعرّف مخمّن.
3. اضغط **تصدير حزمة مستقلة** وانتظر التقرير. يظهر عدد المصدّر والمتجاهل والأخطاء
   والمسار. قد تُتجاهل نصوص بلا قوالب عربية موثقة حتى لو ترجمتها.
4. افتح المسار المعروض في مستكشف الملفات. يوجد داخل مشروع RAT:

   ```text
   exports/release-.../
       game/tl/arabic/....rpy
       manifest.json
       report.json
       report.html
       INSTALL_AR.txt
       translation_patch.zip
   ```

5. افتح `report.html` بالمتصفح. `completed` يعني نجاح تصدير السطور المختارة،
   وليس اكتمال كل اللعبة؛ راجع المتجاهل أيضًا. `partial` يعني وجود أخطاء مع
   تصدير بعض النصوص، و`failed` يعني عدم تصدير نصوص. لا تستخدم حزمة فاشلة.
6. الحزمة لا تغير لعبتك ولا تثبت نفسها. احتفظ بالأصل، واقرأ `INSTALL_AR.txt`،
   واختبر على نسخة منفصلة مطابقة. وجود ملفات عربية وحده لا يضيف زر اختيار لغة
   إلى اللعبة. لإعداد الخط واتجاه الكتابة اتبع القسم 11؛ اختيار اللغة داخل لعبة
   مخصصة قد يحتاج تدخل مطورها.
   لا تستبدل ترجمات موجودة في نسخة اختبارك دون الاحتفاظ بنسخة منها.
7. لحماية عملك، اضغط **إنشاء نسخة احتياطية لمشروع RAT**. يظهر المسار داخل
   `backups/backup-...`؛ يحتفظ بقاعدة الترجمات وإعدادات المشروع وقوالبه المحفوظة.
   لا ينسخ اللعبة أو الصور أو مفاتيح API، ولا توجد استعادة تلقائية فوق اللعبة.

أول تصدير يحتاج ملفات المصدر والقوالب المطابقة للفهرسة؛ إن تغيرت فأعد الفهرسة
والمراجعة. بعد حفظ لقطة القوالب في أول تصدير يمكن إعادة التصدير دون وجود الأصل.
للنطاق والقيود راجع [دليل المرحلة 4](docs/phase4.md).

## 11. الخط العربي وRTL وتجربة التشغيل

**Runtime Layer** ملف إعدادات إضافي اسمه `arabic_runtime.rpy` يعمل داخل Ren’Py،
ويختار الخط والتشكيل والاتجاه عندما تكون لغة اللعبة `arabic`. لا يعيد ترجمة النصوص
ولا يغير ملفات اللعبة الأصلية. **RTL** يعني اتجاه القراءة من اليمين إلى اليسار،
و**fallback** خط احتياطي للحروف التي لا يغطيها الخط الأساسي.

1. افتح مشروع RAT، ثم تبويب **العربية والخطوط / Runtime**.
2. ابدأ بخط **Amiri المرفق**؛ يأتي برخصة تسمح بتوزيعه مع الحزمة. لا تحتاج تنزيل
   خط أو تثبيته في Windows. يمكنك اختيار ملف TTF أو OTF آخر؛ يلزم نص رخصته وتفعيل
   إقرار امتلاك حق إعادة توزيعه قبل حفظ طبقة مفعّلة. مجرد وجود الخط على جهازك
   لا يعني السماح بمشاركته مع الآخرين.
3. لإضافة خط احتياطي اضغط **إضافة fallback ورخصته**. الحد أربعة خطوط احتياطية.
   يمكن أن يكون الأساسي لاتينيًا ويغطي الاحتياطي العربية؛ يشترط وجود خط واحد
   يغطي العربية الأساسية كاملة كي لا تتوزع حروف الكلمة المتصلة بين خطوط مختلفة.
4. اضبط أحجام **الحوار والأسماء والخيارات وHistory وPreferences**. الأحجام بوحدات
   Ren’Py وليست قياسًا ثابتًا على كل شاشة. ابدأ بالقيم الافتراضية، ثم جرّب داخل المحرك.
5. اترك الاتجاه **تلقائي مع تفضيل العربية** للنص المختلط. جرّب RTL الإلزامي
   عند الحاجة؛ لا تقلب ترتيب الحروف أو الأرقام بنفسك. خيار محاذاة الواجهات يضبط
   النصوص القياسية، ولا يعيد تصميم كل شاشة مخصصة في لعبة تلقائيًا.
6. اضغط **فحص الخط والتوافق ومعاينة**. ظهور `font_missing_arabic` يعني نقص تغطية
   أحد الخطوط؛ أضف احتياطيًا مناسبًا أو عد إلى Amiri. الخط المفقود أو غير السليم
   أو غياب رخصة الخط المخصص يمنع حفظ وتصدير الطبقة المفعّلة.
7. المعاينة تستخدم Qt وتعرض قيمة تجريبية مثل Alex بدل `[player_name]`، دون تشغيل
   تعبيرات اللعبة. لا تحذف المتغيرات من ترجمتك؛ المعاينة لا تعدّلها ولا تضمن تطابق
   شكلها مع Ren’Py. يمكن تعديل نص المعاينة لاختبار كلمات إنجليزية وأرقام ووسوم.
8. إذا ظهر إصدار **غير معروف**، لا تعتبر نسخة SDK دليلًا على نسخة لعبتك. تحقق
   من معلومات اللعبة أولًا؛ عند معرفة الإصدار أدخله مثل `8.5.3` وفعّل إقرار
   التحقق اليدوي. تعارض معلومات الإصدار يمنع التفعيل حتى يُحل. لا تكتب رقمًا
   بالتخمين لإخفاء التحذير. يمكنك إجراء المعاينة وإنشاء تجربة SDK دون معرفة نسخة اللعبة.
9. التوافق الفعلي اختُبر على **8.5.3.26051504**. توجد ملفات توافق أصلية لـ8.2+
   مع تحذير للإصدارات غير المختبرة؛ 8.3.7 وما بعده ضمن سلسلة 8.3 محجوب تحفظيًا
   بسبب مشكلة موثقة في النص المختلط. 7.x و8.0/8.1 غير متحققة لهذا المسار، ولا
   يطبّق RAT عليها reshaping يدويًا. لا يحدّث RAT محرك اللعبة.
10. فعّل **تضمين Arabic Runtime Layer عند التصدير** ثم **حفظ إعدادات العربية**.
    تُنسخ الخطوط المرخصة إلى مشروع RAT؛ تغيير الحقول وحده دون الحفظ لا يحدّث التصدير.
11. صدّر حزمة جديدة كالقسم 10. ستجد `game/tl/arabic/arabic_runtime.rpy` والخطوط
    وتراخيصها، و`arabic-runtime.json`؛ تفاصيلها في manifest وتقرير التصدير. إعداد
    Runtime غير صالح يمنع إخراج الترجمات في تلك الحزمة، بدل إخراجها بصمت دون الخط.

لتجربة مستقلة قبل استعمالها مع لعبتك:

1. اضغط **إنشاء مشروع Ren’Py تجريبي** واختر مجلد SDK لديك؛ على هذا الجهاز استُخدم
   `D:\B\777\LC\renpy-8.5.3-sdk`. يحتاج مسار SDK الفعلي، وليس ملف EXE للعبة.
2. يظهر مسار داخل `staging/arabic-demo-...` بمشروع RAT. هذه عينة أصلية للبرنامج
   تستخدم إصدار SDK المحدد؛ لا تُشغّل لعبتك ولا تثبت حزمة عليها.
3. افتح Ren’Py Launcher، واضبط مجلد المشاريع ليشمل مجلد العينة، ثم اخترها و**Launch Project**.
   للمطور توجد طريقة تشغيل مباشرة في [دليل المرحلة 5](docs/phase5.md).
4. تحقق من اتصال الحروف، والحوار واسم الشخصية والخيارات ونماذج السجل والتفضيلات،
   ومن ترتيب `Build 42 / 123` والأرقام `٣٤٥`. جرّب أزرار التعطيل والتفعيل والوضع السابق.

للرجوع دون تغيير الترجمات: أزل علامة تضمين Runtime واحفظ ثم صدّر حزمة جديدة؛ لن
تحتوي ملف التشغيل أو خطوطه. لتعطيل نسخة اختبار سبق وضع الحزمة فيها، أنشئ ملفًا
فارغًا داخل `game/tl/arabic` باسم **`rat_runtime.disabled`** ثم أعد تشغيل اللعبة.
احذر أن يسميه Windows `rat_runtime.disabled.txt`؛ أظهر الامتدادات أولًا. احذفه
لتفعيل الطبقة مجددًا. إن استعملت زر التعطيل في العينة، استعمل زر التفعيل أيضًا،
لأن اختياره محفوظ ضمن تفضيلات تشغيل العينة. التعطيل يستعيد أنماط اللعبة السابقة؛
لا يحذف الترجمات ولا يترجم النص العربي إلى الإنجليزية.

النسخ الاحتياطي لمشروع RAT يشمل الآن الخطوط المستوردة التي تشير إليها إعداداته
وتراخيصها. لا توجد عملية تثبيت أو استعادة فوق اللعبة الأصلية.

## أسئلة سريعة ومشكلات شائعة

| المشكلة أو السؤال | ما الذي تفعله؟ |
|---|---|
| الأزرار وخانات اللعبة معطلة | اضغط **إنشاء مشروع** أو **فتح مشروع** أولًا؛ وأثناء الفهرسة انتظر انتهائها. |
| رسالة تطلب مجلدًا يحتوي `game` | اختر المجلد الأب لـ`game`، وتأكد أن الحزمة فُك ضغطها وأنها لعبة Ren'Py. |
| لا توجد نصوص أو اختفت نتائج | امسح البحث وأعد الفلاتر؛ إن بقي العدد صفرًا راجع التحذيرات ونوع الملفات. |
| تحذير `.rpa` أو `.rpyc` | استخدم تبويب الألعاب المجمعة؛ راجع الإصدار وحالات unsupported وpartial. تغيير الامتداد لا يحل المشكلة. |
| الإصدار «غير معروف» أو المعرف `—` | قد يكون طبيعيًا عند غياب دليل الإصدار أو القالب؛ راجع شرح النتائج أعلاه. |
| SDK مرفوض أو انتهت مهلته | أزل علامة التوليد لإجراء قراءة عادية، ثم راجع جدول أخطاء SDK في دليل المشكلات. |
| أين زر الترجمة أو ملف التعريب؟ | ابدأ من **الترجمة والتقدم**، ثم راجع في المحرر وصدّر من **التصدير والنسخ الاحتياطي**. |
| لماذا لا يعمل Approve؟ | افحص QA، وافتح القفل، وألغ Skip عبر Reject؛ يجب سلامة كل الأسطر المحددة. |
| التصدير صفر أو failed | اعتمد نصوصًا سليمة وتأكد من وجود قوالب arabic موثقة ومطابقة؛ اقرأ report.html. |
| لا أستطيع تعديل سطر | Approved يحتاج Reject، وLocked يحتاج Unlock؛ انتظر انتهاء أي عملية جارية. |
| هل أحتاج إنترنت أو مفتاحًا مدفوعًا؟ | لا للفهرسة وMock؛ الخدمات الحقيقية تحتاج اتصالًا، ومزودات API تحتاج حسابًا ومفتاحًا وقد تكون مدفوعة. |
| هل يجب نسخ `staging` إلى اللعبة؟ | لا؛ هي ملفات عمل وقوالب وليست حزمة تعريب جاهزة للتثبيت. |
| هل Mock ترجمة حقيقية؟ | لا؛ أداة اختبار تعيد النص نفسه، وليست خدمة تعريب. |
| الحروف مربعات أو الخط مرفوض | افحص الخط في تبويب العربية، وجرّب Amiri أو fallback؛ قد تحتاج محارف إضافية لاسم اللاعب وقت التشغيل. |
| طبقة Runtime ترفض الإصدار | تحقق من إصدار اللعبة؛ SDK لا يثبته. الإصدارات القديمة أو ذات المشكلة المعروفة تبقى محجوبة. |
| تبدو المعاينة جيدة واللعبة مختلفة | Qt وRen’Py محركان مختلفان؛ جرّب العينة وافحص الأنماط المخصصة أو وسوم font في اللعبة. |

إذا لم يفتح البرنامج، تعذر فتح مشروع، ظهرت رسالة إنجليزية، أو احتجت إرسال بلاغ،
اتبع [دليل حل المشكلات خطوة بخطوة](docs/troubleshooting.md).

ونتائج المحرر والجودة والتصدير في [تقرير المرحلة 4](docs/phase4-verification.md).

<a id="packed-games"></a>

## 12. الألعاب المجمعة: RPA وRPYC

هذه الخطوات تناسب اللعبة التي لا تظهر نصوصها بالفهرسة العادية:

1. افتح مشروع RAT مستقلًا عن مجلد اللعبة، ثم تبويب **الألعاب المجمعة / Packed**.
2. اضغط **اختيار اللعبة** واختر المجلد الذي يحتوي `game`.
3. اترك استخراج الوسائط معطلًا أول مرة لتقليل المساحة. تظل فهرسة النصوص مفعلة.
4. اضغط **Extract Packed Game** وانتظر. يدعم البرنامج عدة أرشيفات في اللعبة نفسها.
5. راجع أعداد RPA وRPYC والملفات المستخرجة والمفكوكة والفاشلة، ثم جدول الملفات.
   تُحفظ النسخ في `staging/packed` داخل مشروع RAT؛ لا يُكتب شيء في اللعبة الأصلية.
6. إذا ظهرت تعارضات، اختر التعارض ثم النسخة المطلوبة بحسب اسم الأرشيف، واضغط
   **تسجيل اختيار التعارض**. كرر ذلك ثم **تطبيق الحلول المحددة وإعادة الفهرسة**.
   يمكنك اختيار تجاهل ملفات التعارض صراحة. لن يستبدل البرنامج ملفًا مختلفًا تلقائيًا،
   ولن يغيّر قائمة النصوص السابقة ما دامت هناك تعارضات معلقة.
7. إذا بقيت ملفات RPYC دون RPY، فعّل **محاولة فك RPYC** وأعد الاستخراج.
   يحتاج ذلك دليلًا على إصدار **اللعبة**. إذا لم يُكتشف، أدخل إصدارًا تحققت منه
   بنفسك ثم فعّل التأكيد. مسار SDK الموجود عندك لا يثبت إصدار اللعبة.
8. راجع `unsupported` و`partial` وأسبابها. اختُبر قارئ RPYC فعليًا على 8.5.3 فقط؛
   العائلات 8.2–8.5 لها مسار محافظ مع تحذير عند غياب الاختبار الحي. الإصدارات
   القديمة والمعدلة أو المجهولة قد تُرفض. تُحذف شيفرة Python من ناتج التحليل دون تشغيلها.
9. عند نجاح الفهرسة، راجع النصوص في **اللعبة والنصوص** ثم أكمل الترجمة والمراجعة.
   وجود نصوص مستخرجة لا يعني صلاحيتها للتصدير؛ يلزم قالب عربي موثق ومعرفات حقيقية.
10. زر **Clean Workspace** يحذف مساحة التشغيل المحددة في قائمة السجل، ويحفظ
    قاعدة الترجمات والتقارير والتصديرات. بعد التنظيف، أعد الاستخراج إذا احتجت الملفات
    المؤقتة. لا تنسخ مساحة التحليل إلى اللعبة ولا تحاول تشغيلها كلعبة كاملة.

إذا لم تعرف سبب الفشل، افتح ملف Manifest المعروض أسفل الجدول وابحث عن `error_code`.
السجل في `logs/packed-recovery.jsonl` داخل المشروع. للحلول والحدود وأوامر المطور
راجع [phase6.md](docs/phase6.md). لم تُنفذ مرحلة تثبيت التعريب فوق اللعبة.

## للمطور: التثبيت من الشيفرة على Windows

يتطلب Python 3.11+ بنسخة 64-bit. المستهدف مبدئيًا 3.11 و3.12؛ راجع
`docs/compatibility.md` لمعرفة البيئة التي اختُبرت فعليًا.
هذا القسم لتشغيل الشيفرة وتطويرها؛ مستخدم EXE لا يحتاج هذه الخطوات.

```powershell
py -3.11 -m venv .venv
# عند توفر 3.12 بدلًا منه: py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -e ".[dev,llm]"
```

لا يتطلب التشغيل تفعيل البيئة أو تغيير سياسة تنفيذ PowerShell. للاعتماديات الأساسية
فقط يمكن استخدام `python -m pip install -r requirements-core.txt` داخل البيئة.
توجد لقطة بالإصدارات التي اختُبرت على Windows/Python 3.13 في
`requirements-dev-windows-py313.lock.txt`؛ يمكن تطبيقها كقيود تثبيت باستخدام `-c`.
مجموعة `llm` توفر SDK لموصلات المرحلة 3؛ ثبّتها عبر `pip install -e ".[dev,llm]"`
إذا كنت تشغّل الشيفرة وتريد الخدمات الحقيقية. `cloud` و`offline` إضافات مستقبلية.
الفهرسة وMock لا يحتاجان SDK الخدمات، ونسخة EXE الحالية تضمها.

## التشغيل

```powershell
.\.venv\Scripts\python.exe -m rat
# أو بعد تفعيل البيئة: rat-gui
```

تعرض النافذة إنشاء مشروع وفتحه وإغلاقه. عند الإنشاء اختر **مجلدًا مستقلًا لمساحات
العمل**؛ ينشئ التطبيق مجلدًا بمعرّف داخلي لا يشتق من اسم المشروع. لا تختَر مجلد لعبة.
فتح المشروع يتطلب اختيار المجلد الذي يحتوي `project.yaml` و`project.sqlite`.

بعد فتح المشروع اضغط **اختيار مجلد اللعبة** ثم **فهرسة النصوص**. لتوليد قوالب
رسمية حدد SDK وفعّل خيار التوليد؛ يُسمح بذلك للمصدر التصريحي الآمن فقط، وعلى نسخة
عمل منفصلة. المشاريع التي تحتوي Python أو مصدرًا ناقصًا يمكن فهرستها وقراءة قوالبها
الموجودة، لكن لا يشغّلها RAT لتوليد قوالب. راجع `docs/phase1.md` للتفاصيل.

```powershell
.\.venv\Scripts\rat.exe project create --name "مشروعي" --workspace ".local\projects"
# انسخ path من JSON الناتج بدل <project-folder>
.\.venv\Scripts\rat.exe project info --project "<project-folder>"
.\.venv\Scripts\rat.exe scan --game "<game-folder>" --project "<project-folder>"
.\.venv\Scripts\rat.exe scan --game "<declarative-project>" --project "<project-folder>" --sdk "<sdk-folder>" --generate-templates
.\.venv\Scripts\rat.exe mock-demo
.\.venv\Scripts\rat.exe protect --project "<project-folder>"
.\.venv\Scripts\rat.exe providers --project "<project-folder>"
.\.venv\Scripts\rat.exe translate --project "<project-folder>"
.\.venv\Scripts\rat.exe qa --project "<project-folder>"
.\.venv\Scripts\rat.exe export --project "<project-folder>"
.\.venv\Scripts\rat.exe backup --project "<project-folder>"
.\.venv\Scripts\rat.exe arabic --project "<project-folder>"
.\.venv\Scripts\rat.exe arabic --project "<project-folder>" --disable
# يستخدم Mock افتراضيًا؛ لمزود محفوظ أضف --profile، ولاستئناف مهمة أضف --job.
.\.venv\Scripts\rat.exe config-init --output ".local\settings.yaml"
.\.venv\Scripts\python.exe -m rat --config ".local\settings.yaml"
```

`mock-demo` يستخدم عينة مصطنعة مدمجة فقط، ويحمي رموزها ثم يمررها إلى Mock الذي
يعيد النص نفسه مع `simulated: true`، ثم يفحص الاستعادة. ليس ترجمة إلى العربية
ولا اختبار اتصال API، ولا يقبل ملفات ألعاب. `protect` يعرض حماية النصوص المحفوظة.

عند غياب `--workspace` تستخدم إعدادات `app.workspace_dir` ثم Documents عبر
`platformdirs`. إذا لم يتوفر Documents أو لم تسمح الصلاحيات بالكتابة، اختر مجلدًا
آخر صراحة. إعدادات الواجهة الافتراضية في مسار المستخدم الذي يعيده `platformdirs`؛
يمكن معرفة المسار بالأمر:

```powershell
.\.venv\Scripts\python.exe -c "from rat.config.paths import config_dir; print(config_dir() / 'settings.yaml')"
```

السجلات في مسار `platformdirs.user_log_path`، ويمكن تغييره بـ`--log-dir` في CLI
والواجهة. تسجل أحداثًا محددة فقط دون نصوص أو مفاتيح أو تفاصيل استثناءات المدخلات.
ملفات YAML غير سرية، وتُرفض حقول مفاتيح API. `.env.example` أسماء مستقبلية فقط؛
لا يُحمّل التطبيق ملف `.env`. إعدادات المزودين غير السرية في SQLite، ومفاتيحهم
في مخزن النظام عبر keyring؛ لا تُكتب في YAML أو قاعدة المشروع أو logs.

## التحقق

```powershell
.\.venv\Scripts\python.exe -m pytest -c pyproject.toml tests
# مع اختبار SDK الحقيقي؛ استخدم مسار SDK موثوق لديك:
.\.venv\Scripts\python.exe -m pytest -c pyproject.toml tests --renpy-sdk="<sdk-folder>"
.\.venv\Scripts\python.exe -m ruff check .
.\.venv\Scripts\python.exe -m ruff format --check .
# أو: .\scripts\dev.ps1 -Check
```

اختبارات Qt تعمل افتراضيًا بـ`offscreen`. تشمل الاختبارات إعادة فتح المشروع
في عملية CLI جديدة، حفظ النصوص والمراجعات، حماية المصدر والترجمات المعتمدة،
المعاملات والمفاتيح الخارجية، إعدادات YAML الآمنة، موصل Mock دون شبكة، وأزرار الواجهة.
تشمل أيضًا اكتشاف اللعبة وقراءة القوالب وإعادة الاستيراد والترحيل من مخطط المرحلة 0.
وتشمل المرحلة 2 الأقواس المتداخلة والوسوم والهروب والتلاعب بالرموز والخرائط،
وفحص الاستعادة وربطها بالنصوص المستخرجة دون تعديل المصادر أو اتصال شبكي.
اختبارات SDK الحية تُتخطى عند عدم تحديد SDK؛ اختبارات المحلل والجرد والتخزين تعمل
دون SDK. تقرير المرحلة 1 يوثق تشغيل المجموعة كاملة دون تخطٍ مع SDK 8.5.3.
تفاصيل النطاق والقرارات في `docs/architecture.md`، وحدود التحقق في
`docs/compatibility.md`.

الملفات المؤقتة للاختبارات في `.pytest_tmp/` داخل المستودع لتجنب الاعتماد على
صلاحيات مجلد Windows المؤقت. هذا مجلد اختبار مولّد يعيد pytest تهيئته عند التشغيل.
